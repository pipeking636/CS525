# B+树插入和删除节点需要的核心公式：
B+树中节点可以包含的“键”的最大个数为n，n一般在B+初始化时被设置为一个固定值，例如100。
|                | Max ptrs | Max keys | Min ptrs          | Min keys          |
| -------------- | -------- | -------- | ----------------- | ----------------- |
| Non-leaf (non-root) | $( n + 1 )$  |  $n$  | ⌈$\frac{n+1}{2}$⌉ | ⌈$\frac{n+1}{2}$⌉ - 1 |
| Leaf (non-root)     | $( n + 1 )$  |  $n$  | ⌊$\frac{n+1}{2}$⌋ + 1 | ⌊$\frac{n+1}{2}$⌋ |
| Root                | $( n + 1 )$  |  $n$  | $2^*$         | $1$           |
    * 根节点如果是叶节点，则可以有0个键和1个指针；如果是非叶节点，则至少有2个指针和1个键。
    * Min Keys的计算对于删除时触发下溢操作很重要。
        - n为偶数时：用整数除法，可以理解为，非叶子和叶子节点的Min Keys一样，可以统一为(n/2)。
        - n为奇数时：用证书触发，可以理解为，非叶子节点的Min Keys=(n-1)/2，比叶子节点的Min Keys=(n+1)/2 少1。
# B+ 树插入节点的核心逻辑
## 基础规则
1. 键值存储特性：插入的键值需遵循 B + 树结构特性 —— 非叶节点仅存储索引字段值（用于导航），叶节点既存储索引字段值也存储指向主文件的指针，且所有叶节点按键值有序排列并覆盖全部键值。
2. 节点容量限制：每个节点最多容纳n个键和n+1个指针（n为块最大键数），插入时需先判断目标节点是否有剩余空间，无空间则触发节点分裂。
3. 所有的叶子节点有序排列且所有的叶子节点组成一个单向链表。非叶子节点也是有序排列，不存储键值，也不形成链表。
## 插入操作流程
### 步骤 1：定位插入位置
    - 从根节点出发，根据键值大小逐层导航至目标叶节点（非叶节点通过比较键值确定下一层子节点，最终找到键值应插入的叶节点）。
    - 例：要插入一个key值为45的记录，先定位到已存储 [13,23,49] 的叶节点。
### 步骤 2：判断节点是否需要分裂
    - 若叶节点键数 ＜n ：直接插入键值并保持叶节点有序，插入完成。
    - 若叶节点键数 =n ：触发叶节点分裂，分裂后需将新节点的 “最小键值” 插入父节点（若父节点也满，则继续分裂，直至根节点，根节点分裂会使树高 + 1）。
### 步骤 3：B+树节点的分裂操作
    当一个节点中的键的个数大于最大键数n时，需要进行分裂操作。分裂操作会考虑两个部分：\
    1. 分裂节点：将当前节点一分为二，遵循“半满”原则。将中间键插入到父节点中。具体情况分为四种\
    1.1 当n为奇数时：
        1.1.1 叶子节点：因为，n为奇数，所以当一个叶子节点中的键的个数为n时，（n+1）为偶数，可以被2整除，所以分裂后的左右节点中键的个数分别为(n+1)/2和(n+1)/2。\
        例如：n=3, 一个叶子节点当前有3个键[1,4,9], 此时插入一个新的键5，叶子节点会变成[1,4,5,9]。此时节点中的键的个数大于n，需要将该节点分裂。根据“半满”原则，分裂后的节点为[1,4]和[5,9]。5会被插入到父节点中。\
        1.1.2 非叶子节点：因为，n为奇数，所以当一个叶子节点中的键的个数为n时，（n+1）为偶数，可以被2整除，所以分裂后的左右节点中键的个数分别为(n+1)/2和(n+1)/2。但是，将原中间键删除并上推（Push）插入到父节点中。这种情况等价于将分裂后的右节点的第一个键删除并插入到它的父节点中。\
        例如：n=3, 一个非叶子节点当前有3个键[1,4,9], 此时插入一个新的键5，非叶子节点会变成[1,4,5,9]。此时节点中的键的个数大于n，需要将该节点分裂。根据“半满”原则，分裂后的节点为[1,4]和[5,9]。然后将原中间键5，也就是分裂后的右键的第一个key删除并插入到它的父节点。所以，该非叶子节点分裂的最终结果是[1,4]和[9]， 5被上推到了父节点。\
    1.2 当n为偶数时：
        1.2.1 叶子节点：因为，n为偶数，所以当一个叶子节点中的键的个数为n时，（n+1）为奇数，不能被2整除。所以，分裂后的左右节点中键的个数分别为((n+1)/2)+1和(n+1)/2。\
        例如：n=2, 一个叶子节点当前有2个键[1,4], 此时插入一个新的键5，叶子节点会变成[1,4,5]。此时节点中的键的个数大于n，需要将该节点分裂。根据“半满”原则，分裂后的节点为[1,4]和[5]。5会被插入到父节点中。\
        1.2.2 非叶子节点：因为，n为偶数，所以当一个非叶子节点中的键的个数为n时，（n+1）为奇数，不能被2整除。所以，分裂后的左右节点中键的个数分别为((n+1)/2)+1和(n+1)/2。但是，将原中间键删除并上推（Push）插入到父节点中。这种情况下等价于把分裂后的左节点的最后键删除并插入到它的父节点中。\
        例如：n=2, 一个非叶子节点当前有2个键[1,4], 此时插入一个新的键5，非叶子节点会变成[1,4,5]。此时节点中的键的个数大于n，需要将该节点分裂。根据“半满”原则，分裂后的节点为[1,4]和[5]。注意此时和叶子节点不同的是要将原中间键4，也就是分裂后的左节点的最后键删除并插入到它的父节点。所以，该非叶子节点分裂后的最终结果是[1]和[5]。\
    2. 更新父节点：如果当前节点是根节点，需要创建一个新的根节点；如果当前节点不是根节点，需要更新父节和父节点的指针。操作方法和非叶子节点的方法相同。
    3. 特殊场景处理：
        - 根节点分裂：根节点无父节点，分裂后会产生新根（新根存储分裂后的中间键 / 右节点最小键，包含 2 个指针指向原分裂节点），树高增加 1。
        - 多属性键插入：若基于多属性（如 age+salary）建 B + 树，插入时需按 “先比较第一个属性，再比较第二个属性” 的规则排序键值（如 (19,45000)＜(19,100000)＜(19,110000)），分裂逻辑与单属性一致。
    4. 注意点：
        - C语言的正整数除法的结果会自动向下取整，因此上面的公式是正确的，不需要特殊处理。
        - 上面的例子中只体现了Key的情况，在插入和删除key的同时还需要调整相应的指针。例如，在插入一个新的键时，需要将新键插入到正确的位置，并且更新相应的指针。在删除一个键时，需要将删除的键从节点中移除，并且更新相应的指针。
        - 根据上面的说明，我们发现需要先考虑插入后的节点情况再进行分裂操作。因为B+树中Key值是有序排列，所以如果在插入前就先分裂，有可能导致新插入的Key值违法有序性。例如，在插入一个新的键时，需要有序排列，再判断插入后的节点是否超过最大键数n。如果超过，才需要在有序排列的基础上进行分裂操作。

# B+ 树删除节点的核心逻辑
## 删除的基础规则
1. 下溢判断标准：删除后节点键数需不低于 “最小键数”，否则触发下溢处理。最小键数按节点类型区分（n为块最大键数）：

|                | Min ptrs          | Min keys          |
| -------------- | ----------------- | ----------------- |
| Non-leaf (non-root) | ⌈$\frac{n+1}{2}$⌉ | ⌈$\frac{n+1}{2}$⌉ - 1 |
| Leaf (non-root)     | ⌊$\frac{n+1}{2}$⌋ + 1 | ⌊$\frac{n+1}{2}$⌋ |
| Root                | $2^*$         | $1$           |
    * 根节点如果是叶节点，则可以有0个键和1个指针；如果是非叶节点，则至少有2个指针和1个键。
    * Min Keys的计算对于删除时触发下溢操作很重要。
        - n为偶数时：用整数除法，可以理解为，非叶子和叶子节点的Min Keys一样，可以统一为(n/2)。
        - n为奇数时：用整数除发，可以理解为，非叶子节点的Min Keys=(n-1)/2，比叶子节点的Min Keys=(n+1)/2 少1。

2. 处理优先级：下溢后优先尝试从兄弟节点重分配键值(优先左兄弟)，重分配失败则执行节点合并，且均优先选择左兄弟。
## B+树的节点下溢处理流程（underflow）
### 步骤 1：定位删除位置
    - 从根节点导航至存储目标键的叶节点，删除键值及对应指针（若为非叶节点存储的索引键，需先找到其在叶节点的实际位置，仅删除叶节点的键，非叶节点键需保留至无子节点引用）。
    - 例如：删除 5 时，先定位到存储 [4,5,9] 的叶节点，删除 5 后节点变为 [4,9]。
### 步骤 2：判断节点是否下溢
    - 若删除后键数≥最小键数：删除完成，无需额外处理。
    - 若删除后键数＜最小键数：触发下溢处理（重分配→合并）。
### 步骤 3：下溢处理逻辑（重分配和合并）
| 处理方式 |触发条件|	操作逻辑	|父节点更新|
| ---------- | --------- | ------------- | ----------- |
|重分配（优先左兄弟）|	下溢节点的左 / 右兄弟键数＞最小键数（有冗余键）|	- 从左兄弟借 “最大键”（或从右兄弟借 “最小键”），插入下溢节点并保持有序<br> - 同步更新父节点中对应 “分隔键”（确保父节点键值匹配子节点键值范围）|父节点分隔键更新为兄弟节点新的最大 / 最小键  | 
|合并（优先左兄弟） | 兄弟节点键数 = 最小键数（无冗余键）| - 下溢节点与左兄弟（无左则与右兄弟）合并，合并后删除父节点中对应 “分隔键”（两子节点合并后，分隔键失效）<br> - 若父节点因删除分隔键下溢，重复 “重分配→合并” 流程，直至根节点 | 父节点删除分隔键，若父节点下溢则继续处理 |
### 特殊场景
    - 根节点合并：根节点合并后若键数为 0，直接删除根节点，将合并后的子节点作为新根，树高减 1。
    - 多属性键删除：按多属性排序规则定位键值，删除后下溢处理逻辑与单属性一致，仅需确保合并 / 重分配后键值仍按多属性有序。

    1. delete 13:

## 删除操作总结：
    - 删除操作最复杂的是删除一个只有最小Key数量的节点，需要考虑下溢处理。
    - 下溢处理包括向左兄弟借键、向右兄弟借键、跨过父节点向左叔叔借键、合并节点。
    - 删除操作后，需要检查是否导致非叶子节点下溢，若下溢则需要递归处理。
    - 删除操作后，需要检查是否导致根节点下溢，若下溢则需要合并根节点，这可能导致数的高度降低。
